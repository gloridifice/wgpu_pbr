# 异步场景加载

## Purpose

当前 Open、Reload、启动打开及浏览器双击在 PostUpdate 排他系统中一次性读取场景、导入模型、解码图片并准备 GPU 资源，大场景会阻塞窗口和编辑器。本变更将场景加载分成后台 CPU 加载、主线程预算内 GPU 准备及最终排他提交，保持候选成功前旧场景不变。

## Scope and acceptance

### 范围与契约

- 启动、Open、Reload 和浏览器双击共用异步加载入口，不改变版本化 `.scn.ron`、路径安全和材质覆盖语义。
- 单个后台工作线程完成候选 CPU World、校验、世界变换、模型导入、实际材质依赖收集、图片格式转换及环境 SH。CPU 导入按规范化路径去重；GPU 准备不再读场景资产文件。
- GPU 网格与纹理分块上传，环境转换及预过滤分步执行；每帧软预算限制 CPU 准备时间与上传字节，限制在途 GPU 批次，不阻塞等待 GPU。
- 候选使用独立缓存和环境状态，全部完成后才排他提交。失败或取消保持旧实体、缓存、环境、当前路径、保存基线及未保存修改。
- 未保存确认和加载期间，活动场景持久数据只读，暂停旋转行为和相机移动；保留选择、目录浏览、布局与 viewport 尺寸调整。Save and Open 的内部保存例外。
- 忙时拒绝新的场景操作；允许取消。任务编号隔离迟到结果。CPU 导入不可抢占时协作取消，不在帧线程 join。后台最多一个执行任务和一个等待任务。
- 展示真实加载阶段、工作量、取消入口和失败信息；记录准备、提交时间与估算内存。峰值预算超限拒绝候选，不提前卸载旧场景。

### 验收

1. 大资源加载跨帧推进，旧场景继续呈现；后台完成或取消不要求窗口线程同步等待。
2. 模型、覆盖纹理、嵌入图片与颜色空间缓存保持原语义，候选 GPU 准备不进行文件读取或 CPU 图片转换。
3. CPU/GPU 准备失败及取消不损坏活动场景，迟到任务不能提交；请求队列与 GPU 在途工作有界。
4. 加载期间不能通过属性、相机控制或行为系统修改持久组件；取消后恢复可编辑和原 dirty 状态。
5. 成功提交正确更新相机、环境、路径、保存基线、拾取 epoch，并保留旧 viewport 纹理延迟释放。
6. 普通无 GPU 测试、显式 GPU 生命周期验证及构建有真实执行记录；未完成的原生交互或性能验证明确保留，不虚报。

### 非目标与限制

Save、实体 Retry、运行时资产编辑仍同步。不引入 Tokio、完整 Bevy AssetServer、目录预加载、热重载、跨场景 LRU 或并行编辑。Device 与公共资源初始化仍同步。GPU 分配、公共管线初始化和 O(实体数) 的最终提交不可抢占，预算为软限制，不承诺所有帧零尖峰。第三方 glTF/图片导入调用内部不能强制取消或严格限制瞬时解码内存。

与 `persistent-scenes-and-browser` 的关系：它是已交付的同步基线，异步为其原非目标；本包不更改其任务、结果或生命周期。
