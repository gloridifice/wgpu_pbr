## 2. 严重 Bug (Critical)

### 2.1 `Color::with_alpha()` 修改了 z 通道而非 w 通道 ✅

**文件**: `crates/lentille_math/src/lib.rs:51`

```rust
pub fn with_alpha(mut self, a: f32) -> Self {
    self.vec4.z = a;  // BUG: 应该是 self.vec4.w = a
    self
}
```

这会导致 alpha 值被写入蓝色通道，实际 alpha 通道不变。所有使用 `with_alpha()` 的透明物体渲染均受影响。

### 2.2 `color_rgba()` 蓝通道使用了绿色值 ✅

**文件**: `src/editor/gui/components.rs:23`

```rust
let mut c: Color32 = Color32::from_rgba_unmultiplied(
    (color.r() * 255.0) as u8,
    (color.g() * 255.0) as u8,
    (color.g() * 255.0) as u8,  // BUG: 应该是 color.b()
    (color.a() * 255.0) as u8,
);
```

编辑器中光源颜色拾取器显示的蓝色通道实际是绿色值，颜色表示错误。

### 2.3 `RenderTargetSize` 宽高比较逻辑错误 ✅

**文件**: `src/editor/gui/mod.rs:216-218`

```rust
// 条件检查的是 height vs x, width vs y
if target_size.height != size.x as u32 || target_size.width != size.y as u32 {
    target_size.height = size.y as u32;
    target_size.width = size.x as u32;
}
```

条件中的 `.height != size.x` 和赋值中的 `height = size.y` 不一致，导致**每帧都会触发 resize**，无谓释放并重建 G-buffer 纹理。

### 2.4 `refresh_camera_global_bind_group_by_ids` 函数体为空 ✅

**文件**: `crates/lentille_render/src/camera.rs:437-453`

```rust
fn refresh_camera_global_bind_group_by_ids(
    In(to_refresh): In<Vec<Entity>>,
    // ... 许多参数 ...
) {
    // 函数体完全为空！
}
```

Skybox 变更后触发 `RefreshAllCameraGlobalBindGroupCmd`，但实际刷新逻辑从未执行。更换天空盒纹理后全局绑定组不会更新。

## 3. 中等 Bug (Medium)

### 3.1 `TextureUsages::COPY_DST` 重复 ✅ OR

**文件**: `crates/lentille_render/src/asset/load.rs:220-222`

```rust
usage: wgpu::TextureUsages::TEXTURE_BINDING
    | wgpu::TextureUsages::COPY_DST
    | wgpu::TextureUsages::COPY_DST,  // 重复，应为 COPY_SRC
```

HDRI 加载的纹理缺少 `COPY_SRC` 使用权，可能影响后续的 mipmap 生成或纹理拷贝。

### 3.2 `WorldTransform::default()` scale 为 (0,0,0) ✅

**文件**: `crates/lentille_render/src/transform.rs:62`

```rust
impl Default for WorldTransform {
    fn default() -> Self {
        Self {
            position: Vec3::zero(),
            rotation: Quat::identity(),
            scale: Vec3::zero(),  // 应为 Vec3::one()
        }
    }
}
```

虽然 `WorldTransform` 通常由 `Transform` 计算而来不会走 `Default`，但如果某处使用了 `Default::default()`，模型矩阵将塌缩为零。

### 3.3 `sys_render_transparent` 排序逻辑

**文件**: `crates/lentille_render/src/systems.rs:211-219`

```rust
q_objects.iter().sort_by::<&WorldTransform>(|a, b| {
    let result_a = camera.view_proj * a.position.with_w(1.0);
    let result_b = camera.view_proj * b.position.with_w(1.0);
    // 使用世界坐标而非物体中心/包围盒中心
```

透明确物体的远-近排序使用物体原点位置投影，而非实际几何中心或最近点，大尺寸透明物体可能出现排序错误。

### 3.4 平面模型被注释但变量仍计算 ✅

**文件**: `src/lib.rs:121,267-283`

```rust
let plane_model = Arc::new(Model::load(...).unwrap());  // 加载了但从未使用
// ... 70 行后整个 SpawnModelCmd 被注释掉
```

`plane_model` 在场景生成时被加载（涉及磁盘 I/O 和 GLTF 解析），但对应的 `SpawnModelCmd` 被注释掉，造成资源浪费。

## 5. 健壮性问题

### 5.1 过多 `unwrap()` / `panic!()` 在生产路径中

- `ShaderLoader::from_world` — 文件读取失败直接 `panic!()`（`shader_loader.rs:67-68`）
- `Model::load` — GLTF 解析失败的 unwrap 会导致应用崩溃（`lib.rs:122`）
- `surface.get_current_texture().unwrap()` — 窗口表面获取失败直接崩溃（`editor/gui/mod.rs:81`）
- `sys_egui_tiles` 中 `world.resource::<RenderTargetEguiTexId>()` 若未初始化则 panic

**建议**: 对文件 I/O 和 GPU 资源使用 `anyhow::Result` 传播错误，在顶层做 graceful degradation。

### 5.2 `block_on` 在 `FromWorld` 中使用

`RenderState::from_world` 和 `sys_create_surface` 中使用 `pollster::block_on()` 同步阻塞等待异步 GPU 初始化。这在 wasm 环境下会 panic。

### 5.3 着色器编译错误处理静默

`shader_loader.rs:78`：
```rust
Err(e) => println!("? -> {e:#?}"),
```
着色器组合失败仅打印到 stdout，不阻止后续运行，可能导致渲染管线创建时崩溃且难以调试。

## 6. 架构与设计问题

### 6.1 复杂度过高的自定义渲染图系统

`TypeIdGraph` + `RenderStageManager` + `ResourceGraph` + `InsertConfig` 构成了一套基于 `TypeId` 的有向无环图依赖管理系统，用于：
- 渲染资源的初始化顺序
- 渲染 Pass 的执行顺序

对于当前 ~5 个 Render Stage 的规模，这套系统带来较高的认知负担。`bevy_app` 原生的 `SystemSet` + `chain()` 已足够管理依赖。

### 6.2 全局可变状态

```rust
pub(super) static RENDER_RESOURCES_TO_ADD: LazyLock<Mutex<ResourceGraph>> =
    LazyLock::new(|| Mutex::new(ResourceGraph::new()));
```

使用 `static Mutex` 收集渲染资源注册信息，在 `sys_init_window` 中被 `swap` 取出。这种模式在多窗口场景下不安全。

### 6.3 `unsafe` 使用

- `impl_pod_zeroable!` 宏在 6+ 个类型上标记 `Pod`/`Zeroable`，未对所有类型做 layout 验证
- `rpass.forget_lifetime()` 用于绕过 wgpu 的 lifetime 约束（`egui_renderer.rs:131`）

### 6.4 废弃 API 未清理

`app_ext.rs` 中 `add_render_system` 和 `add_render_system_with_custom_schedule` 标记为 `#[deprecated]` 但仍保留。
