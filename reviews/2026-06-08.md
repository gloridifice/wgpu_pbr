# 启动性能优化分析

日期：2026-06-08

## 架构概述

项目使用 `bevy_ecs` + `bevy_app`，渲染资源通过自定义 `ResourceGraph` 延迟初始化。窗口创建后（`PrimaryWindowCreatedEvent`），`sys_init_window` 按拓扑序批量初始化所有 GPU 资源，整个过程在主线程同步执行。

`ControlFlow::Poll` 模式意味着事件循环持续轮询不等待，但资源加载本身是阻塞的。

---

## 瓶颈清单（按发生顺序）

### 1. GPU 适配器 + 设备创建

**位置**：`crates/lentille_render/src/lib.rs:171-183`

**现状**：`RenderState::from_world()` 通过 `pollster::block_on` 同步等待 `wgpu` 的 `request_adapter()` + `request_device()`。

**耗时**：200ms ~ 3s（首次运行或有驱动着色器缓存编译时更长）

**分析**：这是硬件/驱动层面的操作，应用层几乎无法加速。但可以通过以下方式改善用户感知：
- 在等待期间显示启动画面（splash screen）
- 使用 `winit` 的 `EventLoop::run_return` 在创建 GPU 的同时保持窗口响应

**建议**：低优先级，属于基础设施层面。

---

### 2. 默认纹理加载（4 个 PNG 文件）

**位置**：
- `WhiteTexture` — `crates/lentille_render/src/resource/base_assets.rs:74`
- `NormalDefaultTexture` — 同文件 `:89`
- `MissingTexture` — 同文件 `:104`
- `DFGTexture` — 同文件 `:172`

**现状**：每个纹理通过 `UploadedImageWithSampler::load_from_path()` → `File::open` + `read_to_end` + `image::load_from_memory` + GPU 纹理上传。全部在主线程同步完成。

**耗时**：~10-50ms

**建议**：
- White/Missing/NormalDefault 纹理内容极简，可考虑程序生成（纯色 1x1 像素）而非加载 PNG
- DFG 查找表纹理可嵌入二进制（`include_bytes!`），避免运行时磁盘 I/O

---

### 3. 着色器编译（15+ 个文件）

**位置**：各管线资源的 `FromWorld` 实现，通过 `ShaderLoader::load_source()` → `wesl.compile()`

**现状**：
- 每个管线创建时都重新调用 `wesl.compile()`，涉及文件读取 + WGSL 解析 + `#import` 指令解析 + 条件编译
- 累计处理 15+ 个着色器文件

**耗时**：100~500ms（累积）

**建议（P0）**：实现 Naga IR 序列化缓存
- 首次编译后将 `naga::Module` 序列化为 `bincode`/`ron` 写入磁盘缓存目录（如 `%LOCALAPPDATA%/wgpu_pbr/shader_cache/`）
- 后续启动直接反序列化加载 `naga::Module`，跳过整个 WGSL 编译流程
- 缓存键使用着色器源文件路径 + 修改时间戳 + 编译选项哈希，确保版本变更时自动重新编译
- 也可将编译移到后台线程并行执行，但序列化缓存的收益更高

---

### 4. 默认 Cubemap 加载 + 预过滤

**位置**：`crates/lentille_render/src/skybox/mod.rs:47-74` — `DefaultSkybox::from_world()`

**现状**：
- 加载 6 张 cubemap 面图片（JPG） → 合成 `Rgba16Float` 纹理数组
- 运行预过滤管线：多个 render pass 跨 mip level 和 cube face

**耗时**：~50-200ms

**建议（P1）**：
- 预过滤结果是纯 GPU 计算产物，可将 6 张面纹理合并为 lat-long 或 cross-layout 图集，缓存预过滤后的 mipmapped cubemap 为 KTX2/DDS 文件
- 或直接序列化 cubemap 纹理数据 + 预过滤 mip 级别到二进制缓存，下次启动直接上传

---

### 5. 字体文件加载

**位置**：`crates/lentille_render/src/editor/gui/mod.rs:253`

**现状**：`fs::read("assets/fonts/MiSans-Normal.ttf")` 同步读取 TTF 文件

**耗时**：~10-50ms

**建议（P3）**：使用 `include_bytes!` 编译期嵌入字体数据

```rust
// 替换 fs::read 为编译期常量
static FONT_DATA: &[u8] = include_bytes!("../../assets/fonts/MiSans-Normal.ttf");
```

改动量极小，收益稳定。

---

### 6. GLTF 模型加载

**位置**：`src/lib.rs:171` — `sys_generate_plane_scene`

**现状**：
- `Model::load("models/stanford_dragon_pbr.glb", world)` 在主线程同步完成
- 涉及文件读取 → gltf JSON 解析 → 二进制 buffer 提取 → 顶点/法线/切线/UV/索引提取 → 材质纹理加载 → GPU 纹理上传

**耗时**：100ms ~ 5s（取决于模型复杂度，Stanford Dragon 通常 1-2s）

**建议（P2）**：
- **异步加载**：在后台线程完成文件 I/O + gltf 解析，完成后通过 `Commands` 提交到 ECS
- **预序列化缓存**：将解析后的模型数据（顶点缓冲区、索引缓冲区、材质信息）序列化为 `.bin` 文件，启动时直接 mmap 或读取 raw buffer 上传 GPU
- **纹理延迟上传**：模型纹理异步上传，允许在纹理就绪前先以默认材质渲染

---

### 7. HDR 天空盒 + Cubemap 转换 + 预过滤

**位置**：`src/lib.rs:307` — `sys_startup_light_and_environment`

**现状**：
- 可选加载 HDR 图片（`textures/skybox/sky_110_2k.png`）
- 流程：disk I/O → `image::load_from_memory` → RGBE/RGB16 解码 → RGBA16F 转换 → Cubemap 渲染（6 面 render pass） → 预过滤（多 mip level） → 球谐系数计算

**耗时**：~50-500ms

**建议（P1）**：
- 预过滤 Cubemap + 球谐系数全部可预计算并序列化缓存
- 首次加载后写缓存，后续启动直接读缓存跳过所有 GPU 计算
- 缓存 key = 源文件路径 + 文件哈希

---

## 优化优先级

| 优先级 | 优化项 | 预估收益 | 改动量 | 风险 |
|--------|--------|----------|--------|------|
| **P0** | Naga IR 着色器编译缓存 | -100~400ms | 中等 | 低（缓存键含版本哈希） |
| **P1** | Cubemap/预过滤结果缓存 | -100~500ms | 中等 | 低（纯数据序列化） |
| **P2** | GLTF 模型异步加载 | 消除阻塞感知 | 较大 | 中（ECS 时序） |
| **P3** | 字体 `include_bytes!` | -10~50ms | 很小 | 无 |
| **P4** | 小型纹理程序生成 | -10~30ms | 很小 | 无 |

---

## 实施建议

1. 优先实现 **P0 + P3 + P4**（改动可控，短期收益明显）
2. 随后实现 **P1**（进一步缩减 GPU 预计算时间）
3. 最后重构 **P2**（异步模型加载涉及 ECS 系统时序调整，需要更多测试）
